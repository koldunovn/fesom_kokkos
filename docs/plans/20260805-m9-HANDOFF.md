## 5. Traps — read before running anything

1. 🔴 **On Serial every `FESOM_SPEED_*` lever is vetoed without `FESOM_SPEED_FORCE_SERIAL=1`.**
   15 levers shouted it in the first zero-point run, PHASESTATS included. Without that line the
   whole CPU half of a campaign returns 0.00 % differences. `job_m9_ab_cpu` sets it; if you
   write a new CPU job, set it and grep the announce. (L105a)
2. 🔴 **Never put a diagnostic branch in a kernel you intend to time.** On CUDA a never-taken
   branch costs the registers its body needs. This inflated cell ③ to +30 % GPU / +39 % CPU;
   moving it to its own launch gave +13 % / −0.65 %. (L103)
3. 🔴 **Quote the noise floor with every delta** — here ~0.2 %, from legs that must be identical
   (`classic` leg 1 vs `classic_noeps` leg 4). Rep 1 of leg 1 runs ~3 % slow from job warm-up;
   `min`-of-2 absorbs it, and leg 4 being as fast as leg 1 is what excludes leg-order drift.
4. 🔴 **Mesh root is `/pool/data/AWICM/FESOM2/MESHES_FESOM2.1/`** — as `jobs/*` already state for
   dars and ng5. Two hours went into `MESHES/fArc_sorted`, which has the same 638 387 nodes (so a
   node-count check passes) but a different partition set. (L105 corollary)
5. 🔴 **Freeze binaries to immutable `bin/b_<sha8>/`.** Overwriting a reused path failed with
   `Text file busy` while a job was executing it, and two gate jobs went out pinned to the wrong
   build. (L105b)
6. 🔴 **Ranks-per-node is a memory constraint on big meshes.** ng5_w3d at 64 ranks on ONE node
   OOMs; spread over ≥4. **Probe an unfamiliar mesh×ranks point before committing a fleet.**
   Both fleet failures this session were caught by probes. (L105c)
7. **`gpu_fidelity_check.py`'s PASS/FAIL is meaningless for a solver-class lever** — its ceilings
   are calibrated for CUDA-vs-Serial at *identical* arithmetic. Read the magnitudes.
   `job_m9_mevp_bitid CLASS=solver` prints a banner saying so.
8. **Quoting `icedyn` busy alone undercounts the ice cost ~3×.** Use ice+icedyn+iceadv, busy
   **and** wait, which is also the 2019 paper's definition. `TOTAL busy+wait` ≈ the measured
   s/step to ~1 %.
