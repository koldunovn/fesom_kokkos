## 5. Traps — every one of these cost real time here

### 5.1 🔴 `env_cuda.sh` is a BUILD rule, not just a run rule (L77)
`build_m14.sh` sourced `env.sh` (openmpi/4.1.2, `--without-cuda`) for the CUDA build, which
**RPATH-pins** the binary to `/sw/spack-levante/openmpi-4.1.2-mnmady/lib`. **An RPATH beats
`LD_LIBRARY_PATH`, so fixing the RUN environment cannot rescue it.** Symptom: segfault in step 1
with every knob off at `fesom_halo_device.cpp:460` = `MPI_Isend` on a DEVICE pointer, reached from
`fesom_bulk.cpp:727`. It mimicked a merge regression perfectly (CUDA-only, default path, a file no
merge touched). Diagnosed by `addr2line -e <bin> -f -C <addr>` on the Kokkos backtrace + `ldd`/
`objdump -x`. **Check `ldd` on any new CUDA binary.**

### 5.2 🔴 On a Serial build every `FESOM_SPEED_*` lever is INERT without `FESOM_SPEED_FORCE_SERIAL=1`
`src/fesom_speed.hpp:168-170` ("Serial stays legacy"). So `FESOM_SPEED=1` is a **no-op on CPU**, and
any CPU pair testing a speed lever must put FORCE_SERIAL on **BOTH** arms or "best" silently switches
on every M7 lever too. On CUDA the guard is `#ifndef KOKKOS_ENABLE_CUDA` ⇒ levers are live, and a GPU
pair must NOT carry FORCE_SERIAL.

### 5.3 🔴 SE needs a PER-MESH `FESOM_SE_M`
From M12b's CFL probe: **fArc 90, dars 20**, CORE2 M_min=35. The default 50 **ABORTS on fArc**
(`dtbt 18.00 s > limit 11.09 s → M_min=82`) and **inverts the verdict on dars**: at M=50 SE read
+2.32/+1.22 % (a loss); at the tuned M=20 it is −0.70/−3.72 % (a win).

### 5.4 🔴 A control is a SAMPLE — n=1 cannot tell you which measurement is the outlier
I ran ONE placement control, it disagreed with the CORE2 ladder, and I declared the ladder an
artifact and moved the knee to 1536. **N=5 allocations showed the opposite: four agree tightly and
the CONTROL was the outlier.** The plateau at 864→1024→1536 is REAL. Run ≥3 allocations before
believing anything about a ladder's SHAPE.
✅ Still true: allocation variation is real and rung-dependent (1 % at 512, **24 % at 1536**), worst
where the mesh is latency-bound, smallest for rungs using ALL allocated nodes. **A/B gains are
unaffected — both arms always share nodes in one job.**

### 5.5 A byte gate without a SELF control can manufacture a defect
The CUDA gate reported "FAIL — the merge perturbed the device path". It had not: h17 does not
reproduce itself. It also once reported **PASS on two SEGFAULTED runs** because it checked
`diff_snap`'s rc but not the runs' — the same false-pass class as the NaN-blind solver guard.

### 5.6 Optimised partitions: existence ≠ stability
`det` fixed partition **stability**; it did not create partitions at rank counts nobody generated.
M11 only built them where it RACED. Generating more:
- built-in engines → `jobs/m11_zoo_a.sh` (`ARMS=a5_u30`, `A5_A=100`, `A4_A=100`)
- external → **TWO steps**: `scripts/m11_engines.sh <engine> <mesh> <k>` makes a `.part` VECTOR,
  then `jobs/m11_zoo_b_dists.sh` converts it to `dist_N`. It needs **`SRC`, not just `MESHTAG`**
  (with MESHTAG=farc alone it silently partitioned CORE2's mesh), and the vector name must be
  `<mesh>_<engine>_a100_e0.03_k<K>.part` — the engines script's DEFAULT tag omits `_a100_e0.03`
  even though those ARE the defaults. Wrapper: `jobs/job_m14_extpart`.
- 🔴 **CORE2 must be partitioned from the PRIVATE mesh** (`port2/mesh/core2`), never `/pool` —
  `/pool`'s nlvls/elvls are swapped (L73). `SRC_OVERRIDE` added to `jobs/m10_make_bigparts.sh`.

### 5.7 Other standing traps confirmed here
GH200 batch header needs `--cpus-per-task=72 --gres=gpu:4 --gpu-bind=none` (a node is 4×72-core
Grace = 288 cores) · dolpung has **no python3** (aarch64, no modules) — use awk · `snap_every=-1`
at **≥**4096 ranks · the first leg of an allocation is systematically slow ⇒ **discard a warmup leg**.
