## Headline results

1. **The dolpung-twin config is the fastest measured JUPITER configuration at
   every production-relevant point**: Stages/2025 (GCC 13.3 + PSMPI 5.11 +
   CUDA 12.6), vendored Kokkos 4.4.01 unmodified, `FESOM_HALO_STAGE=1`.
2. **Transport at scale (the A.2 warning, confirmed on a WORKING fabric)**:
   device-pointer MPI works on Stage-2026 PSMPI 5.13 (selfchecks silent,
   fidelity PASS, intra+inter-node) and wins the latency corner (core2 g1–g4,
   farc/dars g1–g2, 4–9%) — but **LOSES to STAGE on every big-mesh multi-node
   point** (ng5 g32 +32%, dars g16 +29%, farc g32 +19%). STAGE stays the fleet
   transport.
3. **Stack effect at scale**: same STAGE transport, Stage-2026 (Kokkos 4.7.03 +
   CUDA 13 + PSMPI 5.13) is ~2% faster at core2 g1/g2 but **11–20% slower on
   big meshes at scale** (ng5_g32 0.0869 vs 0.0723; ng5_g128 0.0657 vs 0.0570;
   dars_g16 0.0557 vs 0.0500). Not attributed further (Kokkos codegen vs ptxas
   vs pscom host path — a dedicated probe would be needed; not worth it while
   s25 wins).
4. **Scaling limits (the beyond-g64 probe)**: ng5 peaks at **g128** (512 ranks;
   g256 regresses −14% dp) → **15.9 SYPD@dt240** (sp_cgp, ×1.0110 corr).
   dars knee at g64, marginal to **g128** → **20.8 SYPD@dt240** (sp_cgp,
   ×1.0222). farc peaks g16 (87.7 SYPD@1200), core2 at g2 (169 SYPD@1800;
   190 on s26+device — the one corner where device transport is best).
   Dists exist to ng5 8192 / dars 4096 — the limit is the mesh's comm
   structure, not partition availability.
5. **Host compiler**: clang 20.1.8 == gcc at core2 g1 (0.0426 vs 0.0423 dp),
   fidelity PASS both precisions. gcc stays (nvcc/ptxas make the device SASS;
   host share is ~nothing).
6. **vs dolpung (Addendum-F calibration)**: like-for-like v2 anchors, JUPITER
   is 1.21–1.27× faster (core2 g1 dp 0.0445 vs 0.0564 STAGE; dp_cgp 0.0370 vs
   0.0460; sp_cgp 0.0329 vs 0.0397). Per-point twin columns pending the
   dolpung v2 fleet table push.

## Gate ladder verdicts (J-gates, §3 + Addendum D)

- **Ladder**: device transport on Stage-2025 PSMPI 5.11 is BROKEN (halo
  selfcheck caught corruption; pscom `GPUBufStg:0`) → STAGE, which passed all
  selfchecks (cgpoly 0.000e+00) and beat the dolpung g1 anchor first try.
- **G-det** (platform health): serial np8 rep-pair BYTE-IDENTICAL.
- **J-G1** np1 smoke (private core2 dist_1): PASS. **J-G4** CUDA-DP fidelity:
  PASS at climate-close floor (np4+np8, both stacks, both transports).
- **J-G3** cross-arch drift doc: step-0 vs Levante `m6_baseline_serial` at
  ~1e-18 (pgf only), 10-step drift ≤1.5e-4 (T) — the documented JUPITER floor.
- **SP certification** (m8 lesson SP8): the m7 DP-ceiling checker false-FAILs
  SP; `mp_cuda_gate.py` noise-envelope PASSes (worst 0.50 of allowance at np4).
  At np8 it flagged uice — inspection: **ONE cell** (idx 100098, 0.057;
  next-largest 0.003) = the isolated EVP-flip class the DP checker waives at
  ≤32 entries. `mp_cuda_gate` is max-based and over-triggers on this pattern —
  check isolated-cell extent before believing a single-field FAIL.
- **Lesson (cost: one wrong gate design)**: cross-decomposition snapshots are
  NOT byte-comparable in this port — snap_000000 already differs np2-vs-np8
  (partition-dependent IC interpolation). The certified byte gate is
  same-decomposition only (np8-vs-np8 baseline), as `job_m7_gate_serial` always
  said. Never gate npN-vs-npM.

## Ops notes (JUPITER specifics)

- Both logins and compute are aarch64 → module-based env (`env_jupiter.sh`),
  builds on login nodes fine (~2 min full CUDA build at -j24).
- Stage-2026 CUDA builds need `Kokkos_ARCH_ARMV9_GRACE` (NOT `ARCH_NATIVE` —
  nvcc chokes on gcc-14 SVE intrinsics, `svcntb`); serial builds need NO arch
  flag (Kokkos 4.7 SIMD cmake bug under ARMV9_GRACE host-only).
- `gres=gpu:4 + gpu-bind=none` (Kokkos maps by SLURM_LOCALID) works as on
  dolpung; `--gpus-per-task=1` is the JUPITER-native alternative, also proven.
- ng5_g2 + farc_g2: intermittent "task Killed" legs at the fattest per-GPU
  loading (borderline-memory class); ≥1 rep per precision survived everywhere;
  reruns pending if min-of-2 hygiene matters.
- Booster queue: 28 concurrent jobs ran without AssocMaxJobs friction;
  128–256-node jobs started within minutes. `MaxNodes=UNLIMITED`.
- Fleet cost: full twin fleet (23 points incl. deep rungs) ≈ 100 node-hours
  actual; the whole campaign incl. s26 refleet + spot checks + gates ≈ 300.
